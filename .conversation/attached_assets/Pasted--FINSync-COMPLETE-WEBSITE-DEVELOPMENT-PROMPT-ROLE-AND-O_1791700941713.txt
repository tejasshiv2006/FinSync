# 1. CORE PRODUCT CONCEPT

FinSync helps users manage a limited budget and understand the consequences of financial decisions before spending money.

The website must connect all these financial elements:

* Starting budget.
* Income.
* Current balance.
* Spendable balance.
* Recorded expenses.
* Essential commitments.
* Daily allowance.
* Savings goals.
* Recurring subscriptions.
* Unexpected expenses.
* Financial risk.
* Financial health.
* Projected month-end balance.
* Future financial commitments.

The signature feature is an interactive **What-If Financial Simulator**.

When a user considers buying something, changing a subscription, increasing savings, or dealing with an unexpected expense, the website must instantly preview how that decision affects all dependent financial metrics.

Example:

A user starts with ₹10,000 and simulates a purchase of ₹2,500.

The simulator must calculate the hypothetical balance of ₹7,500 before other adjustments, then recalculate the complete financial plan, including daily allowance, savings feasibility, upcoming commitments, month-end forecast, financial risk, and financial health.

The preview must not change actual transactions until the user explicitly confirms and applies the decision.

All figures must use Indian rupees (₹) and Indian number formatting.

# 8. FINANCIAL CALCULATION ENGINE

Create one centralized, server-side financial calculation module.

Every screen must use the same calculation rules. Do not hardcode dashboard totals or independently calculate balances in different components.

Implement the following concepts.

## Starting and current balance

Current balance is derived from:

Starting budget + recorded income + recorded refunds + permitted adjustments − recorded expenses.

Apply the documented accounting policy consistently. Count each transaction exactly once.

## Reserved funds

Calculate reserved funds from unpaid essential commitments and other explicitly reserved amounts.

Clearly distinguish:

* Current balance.
* Reserved funds.
* Remaining spendable balance.

Never subtract the same commitment twice.

## Daily allowance

Daily allowance is the spendable balance divided by the remaining challenge days, subject to a clearly defined policy.

Use the actual local challenge date to calculate remaining days.

When the challenge expires, display zero remaining days and avoid division-by-zero errors.

Also calculate a recommended discretionary daily budget after considering future essential commitments and savings targets.

## Savings progress

Calculate actual savings contributions relative to the user's target.

Do not count an unconfirmed savings plan as actual savings.

Display the remaining amount and whether the target appears feasible within the available timeframe.

## Forecast

Build a day-by-day forecast for the remaining challenge.

Consider:

* Current balance.
* Expected income.
* Planned essential expenses.
* Future subscription charges.
* Planned commitments.
* Expected discretionary spending.
* Planned savings contributions.
* Optional unexpected-expense assumptions.

Clearly label forecasts as estimates and show the assumptions behind them.

Recurring items must be projected consistently and must not be duplicated.

## Financial risk engine

Create an explainable, deterministic rules-based risk engine.

Assess:

* Whether the forecast becomes negative.
* Ability to cover essential commitments.
* Available emergency reserve.
* Spending relative to the remaining duration.
* Upcoming expensive commitments.
* Savings target feasibility.
* Recurring payment exposure.

Return:

* Low risk.
* Moderate risk.
* High risk.
* Critical risk.

Show the specific factors producing a risk result and suggest practical actions.

Do not misrepresent this rules engine as a machine-learning model or guarantee future financial outcomes.

## Financial health score

Create a documented score between 0 and 100.

Use configurable weights for:

* Essential expense coverage.
* Cash-flow sustainability.
* Spending consistency.
* Savings progress.
* Emergency reserve adequacy.

Display individual components and clear explanations.

Ensure scores are understandable and do not penalize users unfairly for having a lower starting budget.

Do not describe this metric as a credit score.
